# MaiSaka 好友申请处理插件 (Friend Request Handler)

> QQ 好友申请自动化处理插件。它可以将接收到的新好友申请推送到指定的管理员 QQ，并允许管理员直接在私聊中快捷同意或拒绝。
> 有问题请提issue

## ✨ 主要功能

* **详细资料推送**：收到申请后，自动抓取申请人的详细 QQ 资料（昵称、性别、年龄、等级、所在地、个性签名、验证消息等），并私聊推送给所有配置的管理员。
* **快捷指令审批**：管理员可以通过简单的私聊指令（`/同意` 或 `/拒绝`）快速处理申请。
* **自动欢迎与备注**：通过好友申请后，支持自动发送自定义的欢迎语，并可自动设置好友备注。
* **LLM 智能审核**：接入大语言模型自动判断申请人是否为安全用户（非广告、非小号等），无需人工介入即可完成审批。
* **无条件自动通过**：适合不需要任何审核流程的场景，收到申请即自动同意，并通知管理员。

## ⚙️ 配置说明

插件首次加载后，会在 MaiBot 的配置面板中生成对应的设置项。

### 1. MaiBot 插件端配置

在机器人的配置界面（或配置文件）中，你可以按模块设置以下内容：

* **管理员设置** 
* `admin_qqs`: 管理员 QQ 号列表。只有这里的 QQ 能接收到申请推送并使用审批指令。


* **监听设置** 
* `host`: 监听地址，默认 `127.0.0.1`。
* `port`: 监听端口，默认 `18080`。
* `path`: 监听路径，默认 `/maibot/friend_request`。
* `secret`: 签名密钥（可选）。


* **申请处理策略**
* `mode`: 处理策略，三选一（详见下方说明）：
  * `manual` — 手动审批（默认）
  * `llm` — LLM 智能审核
  * `auto_approve` — 无条件自动通过
* `model_name`: LLM 模型名称（仅 `llm` 模式生效），留空使用默认模型。
* `auto_remark`: LLM 通过后是否自动设置好友备注（仅 `llm` 模式生效），备注内容为对方昵称。

> 提示词和备注模板如需自定义，请直接修改 `plugin.py` 中的 `_LLM_PROMPT` 和 `_REMARK_TEMPLATE` 常量。


* **欢迎语** 
* `message`: 同意申请后自动发送的欢迎语。
```
# 注意：欢迎语想实现换行或分段输出请参考如下写法：
  messages = [
      "你好呀新朋友！\n很高兴认识你~",
      "今天有没有什么开心的事呀~",
  ]
# 换行一定要用 \n ！！！！反斜杠，是\ ！！！而不是问号下面那个/ ！！！！
```


* **头像配置**
* `send_avatar`: 推送好友申请通知时，是否在文本上方附带申请方的 QQ 头像。
* `avatar_size`: 头像尺寸（默认值640尽量别动），常用值: 100/140/640。

## 📋 处理策略详解

### `manual` — 手动审批（默认）

与之前版本行为一致：收到好友申请后推送给管理员，管理员通过 `/同意` 或 `/拒绝` 指令处理。

### `llm` — LLM 智能审核

开启后，bot **不再发送申请消息给管理员等待审批**，而是自动将申请人的信息（不含图片）发送给 LLM 判定是否为安全用户。

* LLM 判定"通过" → 自动同意申请，如果 `auto_remark = true` 则自动设置备注，之后发送欢迎语。
* LLM 判定"拒绝" → 自动拒绝申请。
* LLM 调用失败 → 自动回退到 `manual` 模式（推送给管理员手动处理）。

### `auto_approve` — 无条件自动通过

> ⚠️ **风险警告：请谨慎开启此模式！**
>
> 该模式会**无条件自动通过所有好友申请**，不做任何审核。这意味着广告号、恶意用户、机器人等都会被直接加为好友。
>
> **仅建议在以下场景使用：**
> * 测试环境
> * 完全不在意好友列表安全性的公共 bot
> * 有其他层面的安全防护兜底
>
> **生产环境中如非必要，请勿开启此策略。**

开启后，收到好友申请立即自动同意，同意后将申请人信息（含头像）通知管理员（仅做通知，不带审批命令），然后发送欢迎语。

### 2. NapCat 端配置

为了让插件能收到好友申请，你需要前往 NapCat 的配置界面，添加一个 **HTTP 客户端 (HTTP Post)** 推送目标：

* **URL**: `http://127.0.0.1:18080/maibot/friend_request` （请根据你在插件中配置的 host, port, path 进行替换）。
* **Token / Secret**: 如果你在插件的 `webhook.secret` 中填写了密钥，请在这里填入相同的值；如果插件端留空，则此处也留空。

## 🚀 使用方法

### manual 模式（默认）

当有用户添加麦麦为好友时，管理员 QQ 会收到类似如下的推送消息：

```
[对方头像]
📩 收到新的好友申请
QQ号: 123456789
昵称: 张三
性别: 男
年龄: 22
验证消息: 麦麦我喜欢你
通过申请请发送：/同意 123456789 [备注]
拒绝申请请发送：/拒绝 123456789
```

**管理员审批指令：**

| 指令 | 说明 | 示例 |
| --- | --- | --- |
|  `/同意 <QQ号> 备注`  | 同意该用户，并改为指定备注，留空则不改，并发送欢迎语 | `/同意 123456789 牢麦` |
|  `/拒绝 <QQ号>`  | 拒绝该用户的好友申请 | `/拒绝 123456789` |

> **注意：** 审批指令需要管理员和机器人处于**私聊状态**下发送，且发送者的 QQ 必须在 `admin_qqs` 列表中。

### llm 模式

无需管理员操作。申请到达后自动由 LLM 判定，通过则自动同意并设置备注和发送欢迎语，拒绝则自动拒绝。若 LLM 调用失败则回退到 `manual` 模式。

### auto_approve 模式

无需任何审核。申请到达后立即自动通过，管理员会收到如下通知（仅告知，无审批命令）：

```
[对方头像]
✅ 已自动通过好友申请
QQ号: 123456789
昵称: 张三
性别: 男
年龄: 22
验证消息: 麦麦我喜欢你
```

## 📁 目录结构与数据存储

插件会在自身目录下自动生成一个 `data` 文件夹用于持久化数据：

* `data/state.json`: 用于记录**待处理的申请列表**和**已推送的事件 Flag**。这保证了即使机器人重启，之前的申请依然可以用指令处理，并且启动补漏不会重复推送已经通知过的申请。无需人工干预此文件。
